# MPS Artifact Guidance v1.0

Create only artifacts applicable to the product.

## `PRODUCT-BLUEPRINT.md`

Include purpose, context, users, problems, value proposition, outcomes, principles/guardrails, approved scope, key workflows, policy summary, release intent, assumptions, gaps, risks, downstream status, and maintenance rules.

## `OUTCOMES-METRICS.md`

Map user/business outcomes to metrics, definitions, baselines/targets or directions, guardrails, instrumentation status, owners, and interpretation limits.

## `USER-ROLE-MODEL.md`

Define actors, eligibility, context, jobs/problems, responsibilities, intended actions/authority, visibility, and relationships. Distinguish product intent from MTS enforcement.

## `SCOPE-RELEASE-PLAN.md`

Define capabilities/features by release, MVP coherence, Now/Next/Later, exclusions, dependencies, experiments, assumptions, launch/validation criteria, and change control.

## `WORKFLOW-CATALOG.md`

Map workflow IDs to actors, triggers, states, main/alternate/failure/recovery paths, rules, requirements, MDS patterns, MTS capabilities, and acceptance IDs.

## `REQUIREMENTS-RULES.md`

List traceable requirements and business rules with status, priority/release, rationale, dependencies, downstream impacts, and implementation status.

## `ACCEPTANCE-CRITERIA.md`

Map criteria to requirements, actors, workflows, rules, release, MDS/MTS responsibilities, test method, and evidence.

## `implementation/PRODUCT-IMPLEMENTATION.md`

Map approved IDs to actual repository paths, code, migrations/configuration, MDS/MTS artifacts, tests, implementation status, and known gaps. Never invent paths.

## `qa/MPS-QA.md`

Define applicable scope, workflow, rule, acceptance, role, metric-readiness, and downstream synchronization checks with expected evidence.

## Artifact truth

State what is approved, implemented, and validated now. Mark drafts and stale artifacts accurately. Do not duplicate canonical state unnecessarily.
